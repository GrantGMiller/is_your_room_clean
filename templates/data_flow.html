Data Flow Between Systems

Is Your Room Clean — last reviewed August 2026

This document describes every system our application exchanges data with, what data moves between them, and how each connection is secured. It supports our answers to Ring Appstore's technical safeguards questionnaire.

Flow-by-flow detail

Path Data exchanged Protection
Browser ↔ Ring Account-linking authorization (user clicks Confirm in the Ring app) TLS Handled entirely within Ring's own app/site
Ring → Flask App OAuth authorization code, access/refresh tokens, device events (webhooks) TLS HMAC-SHA256 Webhook payloads verified before processing
Flask App → Ring API requests for device list and image snapshots, authenticated with the linked account's access token TLS OAuth Bearer token
Flask App → Google Gemini A single room snapshot image (low resolution) per analysis request, plus a fixed prompt TLS Image not persisted by our app beyond ~1 hour; no other identifying data included in the request
Flask App ↔ Database Ring account identifier, email, OAuth tokens, cleanliness scores/summaries Local to server Not exposed externally; access restricted to the application process
Flask App → Email Provider Passwordless login links; would carry incident notifications if needed TLS
Browser ↔ Flask App Dashboard views, session cookie, contact form submissions TLS Signed session cookie

Notes

Room snapshot images are not retained beyond approximately one hour and are not stored in the database. No image data is shared with any party other than Google Gemini, and solely for the purpose of generating a cleanliness score.
